# Separate the planning and result surfaces

An interactive Codex session backed by the local Codex CLI will be the only surface for grilling, plan review, and Plan Approval; Codex Desktop may provide that UI but is not the execution runtime. GitHub Issues will act as the unattended queue and audit record, while GitHub will surface only a Delivery Pull Request or Terminal Blocker as an Attention Event after execution starts. Version one will not add Slack, email, or a custom dashboard; this accepts dependence on two existing products in exchange for minimizing owner monitoring and avoiding another interface to build and operate.
